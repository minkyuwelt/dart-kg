## DuckDB 잠금 설명 정정 + 재시도 (웹, fix/duckdb-lock-docs)
- PR #7 리뷰 중 "노트북은 `read_only=True`로 열면 파이프라인과 함께 쓸 수 있다"는 설명이 틀린 것을 발견
  - duckdb 1.5.6에서 확인: 다른 프로세스가 읽기 전용으로 열고 있으면 쓰기 연결이 막히고, 쓰는 중이면 읽기 전용 연결도 막힘
  - Jupyter에서 연결을 열어 둔 채 두면 다음 날 07:00 수집이 실패하고, 재시도도 없어서 그날 수집이 빠짐
- 해결
  - Dagster 자산은 `write_connection()`으로 연결: 잠금에 걸리면 `RetryRequested`로 5분 뒤 다시 시도(최대 3번). 연결을 DART 호출 전에 열기 때문에 재시도해도 API 호출 수는 늘지 않음
  - 품질 검사(asset check)는 읽기만 하므로 `read_only=True`로 변경
  - CLAUDE.md, README, `duckdb_store.py`의 설명을 고치고, 결정 기록(0001)에는 원문을 지우지 않고 정정 문단을 덧붙임
  - 오프라인 테스트 4개 추가(`tests/test_duckdb_lock.py`): 다른 프로세스의 읽기 전용 연결이 쓰기를 막는지, 잠금 시 재시도 3번 후 실패하는지, 그동안 수집 함수가 불리지 않는지, 잠금이 없으면 성공하는지
- README의 `python -m venv` → `python3 -m venv` (Ubuntu에는 `python` 명령이 없음)

  - 스케줄은 Dagster 인스턴스(dagster_home, DuckDB와 별개)에서 최신 `target_corps` 실행 기록을 읽음. 기록이 없으면 SkipReason으로 건너뜀
  - CLAUDE.md에 "스케줄·센서는 DuckDB를 열지 않는다" 원칙 추가
- 테스트 4개 추가(`tests/test_schedule.py`, 총 26개): 기록 없으면 건너뜀, 파티션과 대상 목록의 교집합만 수집, **다른 프로세스가 DuckDB에 쓰는 중에도 스케줄이 run을 만듦**, `target_corps`가 메타데이터와 파티션을 남김

### 막힌 점
- 노트북의 실제 Dagster 인스턴스에 남은 `target_corps` 기록은 수정 전 것이라 메타데이터가 없었음 → 그대로 두면 다음 날 스케줄이 건너뜀
- 테스트에서 `DagsterInstance.ephemeral()`로는 스케줄 컨텍스트를 만들 수 없었음 ("no instance reference")

### 해결 방법
- `target_corps`만 다시 실행(API 0건) → 대상 59곳 기록. 스케줄 미리보기: 11/24 run 59개, 12/1 run 118개
- 테스트는 임시 폴더 인스턴스(`dg.instance_for_test()`)로 바꿈
- **다른 노트북·새 환경에서는 병합 후 `target_corps`(또는 `targets_job`)를 한 번 실행해야 매일 스케줄이 동작함**

## 공시 목록 백필 (feat/backfill-disclosures)
- 59곳 × 71개월 = 4,189개 파티션 전부 완료. 공시 86,893건(회사 58곳, 2021-01-04 ~ 2026-11-23), API 호출 4,661건(파티션 4,175개 + 페이지 넘김 + 재실행), 첫 실행 29.0분. DuckDB 파일 84.5MB
- Dagster 화면 백필(파티션마다 프로세스를 띄워 몇 시간) 대신 프로세스 하나에서 도는 스크립트(`src/pipeline/backfill.py`)로 실행. 파티션마다 완료를 Dagster에 기록해서 화면에서도 채워진 것으로 보이고 매일 스케줄과 이어짐
- 원본 응답 4,735건 중 2,209건(47%)이 "데이터 없음"(013). 작은 자회사는 공시가 없는 달이 많음
- 공시 종류 상위 5: 증권발행실적보고서(18,800), 투자설명서(14,908), 일괄신고추가서류(12,836), 효력발생안내(10,692), [기재정정]일괄신고서(10,593). 자산운용사·증권사의 펀드·발행 관련 공시가 대부분이고, 지배구조·관계 질문에 쓸 공시는 전체의 작은 부분 → Phase 3에서 보고서 종류로 거르는 단계가 필요
- 사업보고서를 낸 회사 31곳 (0002에서 2024년 이후 표본으로 센 30곳보다 1곳 많음)

### 막힌 점
- DART 접속 타임아웃으로 파티션 11개 실패. 연속으로 나지는 않아서 멈추지 않고 끝까지 돎
- 품질 검사 "rcept_no 앞 8자리 = 접수일"이 9,695건(11%) 실패 → 검사 전제가 틀렸음. 대부분 +1일이고, 자산운용사 '효력발생안내'처럼 문서가 만들어진 다음 날 접수되는 경우
- 우리금융경영연구소는 2021년 이후 공시 0건 (대상 59곳 중 실제 공시가 있는 곳은 58곳)
- 백필 스크립트가 다른 브랜치에만 있어서, 실험 브랜치에서 재실행하니 모듈을 찾지 못함

### 해결 방법
- 완료 파티션을 건너뛰는 설계 덕에 재실행 한 번(API 13건)으로 11개를 채움
