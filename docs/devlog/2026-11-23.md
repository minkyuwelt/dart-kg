## PR #5(Airflow + PostgreSQL docker-compose) 노트북 검증 → 기술 스택 재검토
- 웹에서 만든 PR #5를 노트북에서 띄워 체크리스트를 모두 확인함: postgres healthy, Airflow 헬스 체크 정상, `airflow` DB·`vector` 확장 있음, 컨테이너에서 `src` 임포트 성공. 메모리는 Airflow 1.17GB, PostgreSQL 70MB
- 검증 도중 "PostgreSQL·Airflow를 왜 쓰는가"를 다시 따져 봄. 요구사항에서 출발한 근거가 약해서 비교를 처음부터 다시 함
- 결론: **DuckDB(원본) + Dagster(파이프라인) + Neo4j(그래프·벡터·전문검색)**. 근거는 `docs/decisions/0001-tech-stack.md`
  - 핵심 요구사항 "근거 공시와 함께 관계를 답한다"에서는 벡터로 찾은 공시 청크 → 회사·임원 → 지분 경로를 한 번에 탐색해야 함 → 벡터를 Neo4j에 둠
  - 그러자 원본 저장소에 서버형 DB가 필요한 이유가 사라짐 → DuckDB 파일
  - 데이터가 원본 → 정규화 → 그래프·임베딩으로 파생되는 구조 → 자산 중심인 Dagster
- PR #5는 검증 결과와 종료 사유를 코멘트로 남기고 닫음. 컨테이너·이미지·빈 DB 폴더(`data/postgres`) 정리

### 막힌 점
- `docker compose up`에서 `port is already allocated`: 노트북에서 다른 수업 프로젝트 컨테이너가 5432(db-pg)·8080(kg-19-pipeline Airflow)을 이미 쓰고 있었음. Neo4j 포트(7474·7687)도 사용 중
- Airflow가 "비밀값이 5자 미만이라 로그에서 가릴 수 없다"는 경고를 냄 (`POSTGRES_PASSWORD`가 4자)
- 처음 재검토에서 "새 기술을 배워 보자"는 쪽으로 기울었는데, 그건 선정 이유가 될 수 없음

### 해결 방법
- 포트를 `.env`로 바꿀 수 있게 고쳐서(5433/8081) 검증은 마침. 스택이 바뀌어 이 수정은 버렸지만, 앞으로 Docker 서비스의 노트북 쪽 포트는 `.env`로 바꿀 수 있게 하기로 CLAUDE.md에 적음
- 비밀번호 문제는 PostgreSQL을 쓰지 않게 되어 해소됨
- 새로움은 기준에서 빼고, 요구사항(F/N/C) 번호를 인용하지 못하는 이유는 버림. 그 결과 dbt는 "단순한 대안(SQL 파일 + Dagster asset check)으로 충분"해서 탈락시킴
