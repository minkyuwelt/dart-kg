# 0003. PR마다 테스트 자동 실행: GitHub Actions

- 날짜: 2026-11-23
- 상태: 채택

## 배경

이 프로젝트는 웹 Claude Code와 노트북(VS Code) Claude Code가 각자 PR을 올리고, GitHub에서 합친다 (CLAUDE.md "웹 ↔ VS Code 협업 규칙"). 지금까지 테스트는 노트북에서만 돌렸다.

오늘(2026-11-23) 실제로 있었던 일:
- PR #9는 #8보다 먼저 갈라져 나와 `definitions.py`에서 충돌했다. 충돌을 해결한 뒤 새 자산 2개가 잠금 재시도를 빠뜨린 채 남아 있었고, 사람이 읽다가 발견해 고쳤다.
- PR #9, #10은 리뷰 전에 병합됐다. 병합 버튼을 누르는 시점에 "테스트가 통과했는가"를 PR 화면에서 바로 확인할 방법이 없었다.
- 웹에서 만든 PR은 "미검증"으로 올라가고, 노트북에서 테스트를 돌려야만 확인된다. 노트북이 백필 중이면 그동안 확인할 수 없다.

## 요구사항

| ID | 내용 |
|---|---|
| R1 | 어느 쪽(웹·노트북)에서 올린 PR이든, 병합 전에 오프라인 테스트와 Dagster 정의 검사 결과가 PR 화면에 보일 것 |
| R2 | DART API를 호출하지 않을 것 (일일 한도 보호). API 키를 GitHub에 올리지 않을 것 |
| R3 | 노트북이 꺼져 있거나 다른 작업 중이어도 돌 것 (C1) |
| R4 | 운영할 서버나 비용이 없을 것 |

## 후보

| 기준 | 지금처럼 노트북에서만 | git pre-commit 훅 | **GitHub Actions** |
|---|---|---|---|
| R1 PR 화면에 결과 | ✕ 사람이 PR 설명에 적음 | ✕ 로컬에서만 | ◎ PR 체크로 표시 |
| R1 웹에서 올린 PR | ✕ | ✕ 웹 환경에 훅 설정이 따로 필요 | ◎ |
| R2 API 미호출 | ◎ | ◎ | ◎ 테스트가 가짜 응답만 씀, Secret 없음 |
| R3 노트북과 무관 | ✕ | ✕ | ◎ |
| R4 서버·비용 | 없음 | 없음 | 없음 (공개 저장소는 무료) |

## 결정: GitHub Actions

`.github/workflows/tests.yml`: PR과 main push마다 `python -m unittest discover -s tests -t .`와 `dagster definitions validate`를 Python 3.12·3.13에서 실행한다.

- **실제 API 검증은 계속 노트북에서 한다.** CI는 "코드가 깨지지 않았는가"만 본다. 웹 PR의 "미검증" 표시 규칙은 그대로 둔다.
- 테스트가 실수로 DART를 호출해도 가짜 키(`ci-dummy-key`)라서 거절된다.

## 비용·리스크

- 실행 시간: 패키지 설치 포함 수 분. 공개 저장소라 무료
- 노트북의 Python 버전이 3.12·3.13이 아니면 matrix를 맞춰야 한다 (확인 필요: 노트북에서 `python3 --version`)

## 다시 판단할 조건

- 실제 API를 부르는 통합 테스트가 필요해지면 → CI가 아니라 노트북에서 돌리는 별도 명령으로 둔다 (한도·키 보호)
