# 사용자·업무 질문·차별점 (2026-11-25)

- 상태: **초안**. 사용자 결정 2026-11-24: "취업용 포트폴리오지만 실제로 쓸 도구만큼의 실용성이 있어야 한다. 살을 붙이는 방향으로, 비슷한 서비스와 차별되는 지점을 만든다"
- 쓰는 법: 앞으로 기능을 넣을지 말지는 **2절의 업무 질문 중 어느 것을 돕는지**로 판단한다. 아무것도 돕지 않으면 넣지 않는다

## 1. 누가 쓰나

**금융지주를 들여다보는 사람**: 담당 애널리스트·기자, 계열사 IR·준법감시 담당, 지배구조를 공부하는 학생.
공통점은 "공시는 다 공개되어 있는데 **여러 공시를 가로질러 맞춰 보는 일**을 손으로 한다"는 것이다. 사업보고서 한 권은 DART에서 잘 보이지만,
59개 회사 × 여러 해를 사람·회사·문장 기준으로 꿰는 것은 아무 도구도 해 주지 않는다.

개인 투자자는 1차 사용자가 아니다(주가·실적 정보를 원하는데 우리는 그것을 다루지 않는다, 10절 "하지 않는 것").

## 5. 현실 제약

- **어디서 돌리나.** 노트북은 과정 끝에 반납. DuckDB 파일은 코드로 다시 만들 수 있지만(약 5,000건 호출), 임베딩 30만 조각은 GPU 없이 하루가 넘는다 → 모델 결정 뒤 벡터를 Parquet로 내보내 보관하는 방법을 0009에 적는다
- **LLM 비용.** 답변 생성(PR 9)은 외부 API를 쓴다. 질문당 비용 상한과 하루 한도를 0010에서 정한다. 검색과 변화 리포트 1차는 LLM 없이 돌아야 한다(비용 0, 추측 0)
- **시간.** 변화 리포트와 화면은 각각 PR 하나 크기를 넘지 않게 자른다. 넘으면 다음 Phase로 미룬다

## 6. 하지 않는 것

주가·실적 예측, 뉴스 크롤링, LLM이 원문에서 관계를 추출해 그래프에 넣기, 범용 금융 온톨로지 구축(FIBO는 어휘 대응표만), 개인 투자자용 알림 서비스.
전부 신뢰를 떨어뜨리거나(추측), 검증 비용이 크거나(뉴스), 이미 남이 더 잘 한다(주가).
